# Genex crate migration implementation plan and ledger

> **For agentic workers:** This document is the dependency-ordered ledger for the staged Codex-to-Genex migration. Update the row for every crate after its repository-wide audit and after each migration commit.

**Goal:** Audit every workspace crate for remaining `codex` references, migrate names that are safe to rename to `genex`, record explicit compatibility decisions for all others, and commit/push each completed slice.

**Architecture:** The workspace dependency graph determines the stable inspection order. Each crate is searched locally first, then its repository-wide producers and consumers are audited. Internal Rust/package/build names migrate in place when they do not alter active persisted, protocol, external, packaging, or security contracts; those contracts are retained or deferred with evidence.

**Tech Stack:** Rust workspace, Cargo metadata, `rg`, `jq`, `just crate-dependency-graph`, `just check --tests`, `just check`, and `just generate` when generated artifacts are affected.

## Global constraints

- Work directly on `main`; do not create a worktree.
- Sort by direct workspace dependency count, then direct dependent count, then crate name.
- Keep this table as the authoritative progress ledger; every crate must end as `migrate-in-place`, `retain`, `defer`, or `no-match`.
- Audit producers and consumers before changing a production match.
- Preserve active security behavior, runtime platform fallbacks, persisted-data identifiers, protocol/schema contracts, package layouts, and external environment contracts unless a separate audit explicitly authorizes migration.
- For Rust changes, run `just check --tests` and `just check`; run `just generate` when generated artifacts may be affected.
- Do not run standalone tests unless explicitly requested.
- Commit and push each completed migration slice; record the commit in this ledger and in the compatibility inventory.

## Per-crate workflow

1. Run `rg -n -i --hidden --glob '!.git' 'codex' <crate-directory>`.
2. For every match, classify definition/producer, consumer, test-only use, generated content, external contract, persisted/protocol name, or security/platform behavior.
3. Record the explicit decision in this table and in `docs/pre-release-compatibility-inventory.md` before editing production code.
4. Migrate only the approved in-place names, preserving consumers and contracts.
5. Run the required checks and inspect `git diff --check`.
6. Commit and push; record the commit hash and final status here.

## Declaration-led cross-crate migration

### 契約境界の意味

残存宣言についての「外部契約」は、workspace 外の利用者だけを指さない。定義 crate 以外の workspace consumer、実行時の provider endpoint/auth、app-server client、既存の thread history・rollout trace・JSON Schema など、名前を変更すると同時移行が必要になる相手を指す。

| `GenexResponsesHeaders` | core/client・thread extension と Responses HTTP/WebSocket endpoint | endpoint header/auth routing。型名リネーム済み、値と経路は保持 |
