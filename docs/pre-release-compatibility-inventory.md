# Pre-release Compatibility Inventory

This inventory is maintained by the
[pre-release compatibility-layer removal plan](superpowers/plans/2026-09-19-remove-pre-release-compatibility-layers.md).
The repository is a pre-release fork with zero external users, so historical
upstream contracts may be removed. A match is a candidate only when its
producer/consumer audit shows that it is not current runtime behavior.

Related references: [design spec](superpowers/specs/2026-09-19-remove-pre-release-compatibility-layers-design.md),
[provider decoupling plan](provider-decoupling-plan.md),
[provider-specific crate/capability audit](provider-specific-crates.md), and
[Hawk result analysis](hawk-codex-cli-result-analysis.md).

## Decision categories

- `remove`: exists only to read, write, migrate, replay, or describe an
  obsolete contract. The owning cleanup task may delete it.
- `retain`: required by a current in-repository producer/consumer, supported
  platform, security behavior, or provider-neutral capability.
- `migrate-in-place`: has a current consumer, but the canonical producer and
  representation will be made explicit before the compatibility path is
  removed.

### Genex all-crate migration baseline (2026-10-03)

The naming migration now treats repository-owned protocol, schema, persisted,
CLI/configuration, UI, package, and build names as migration candidates after
their producers and consumers are audited. High fan-out, public visibility,
or the fact that a name is serialized is not, by itself, a reason to retain
the Codex spelling in this pre-release fork.

The refreshed Cargo metadata audit contains 123 workspace packages. A
case-insensitive `rg` scan of each package directory found Codex matches in 76
members and no matches in 47 members. A Rust-only identifier scan found
Codex-shaped matches in 74 members and no Rust matches in 49 members. The
previous 82/41 Rust coverage counts were stale and are superseded by
`target/genex-symbol-audit/workspace-coverage.tsv` and
`target/genex-symbol-audit/rust-symbols.tsv`.

Rows previously labeled `defer` or `retain/defer` are provisional execution
labels, not final retention decisions. Each must be reclassified as
`migrate-in-place`, `remove`, or `retain`. `retain` is limited to OpenAI
endpoint-required fields/URLs/auth/model identifiers, external
OpenAI/upstream or third-party identifiers, historical/legal records, names
where `codex` is only a substring of another word, external repository URLs,
and active external/security namespaces whose replacement would strand state.
Provider-specific capability findings remain separate follow-up candidates.

The search is intentionally broad:

```bash
rg -n -i 'legacy|compatib|deprecated|deprecat|migration|fallback|historical|serde\(alias' \
  crates docs --glob '*.rs' --glob '*.md' --glob '*.toml' --glob '*.json'
rg -n -i 'image_generation|image_generation_call|image_gen' crates \
  --glob '*.rs' --glob '*.json' --glob '*.ts'
```

Generated schemas and tests are grouped with the source symbol that produces
them. Ordinary names such as `rename_all`, dependency alias expansion,
heuristic fallback, and migration of a currently supported external-agent
import are not removed merely because the search matched them.

## Ordered cleanup slices

The slices are executed in this order so each later boundary can rely on the
earlier one being free of obsolete persisted data:

1. persisted rollout and thread-history readers/migrations;
2. protocol and app-server aliases/schemas;
3. CLI, config, and import compatibility;
4. UI, observability, and runtime shims;
5. build-system and experimental scaffolding;
6. final dependency and documentation audit.
